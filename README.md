> в [`rag/`](./rag/README.md). Он включает Chroma, BM25/Dense/CLIP, гибридное RRF,

>

> синхронизирует гардероб с модулем поиска, вызывает LLM (Qwen или любую OpenAI-совместимую
> модель), проверяет выбранные вещи и отдаёт образ по контракту фронтенда, в том числе потоком SSE.
> React-чат использует SSE при `VITE_USE_REAL_BACKEND=true` (по умолчанию — клиентский симулятор).

## КТ-2: RAG по капсуле Лукбука

Отдельный стенд индексирует карточки из той же базовой капсулы, что и Лукбук. Собственный обратный индекс BM25 передаёт до трёх карточек локальной Qwen. Интерфейс показывает ответ со ссылками или отказ, а выдачу поиска — отдельно. Основной чат, его гибридный поиск и данные пользователя этот режим не меняет.

Из каталога `backend/`, с Python 3.11+ и установленной Ollama (если она не запущена, выполните `ollama serve` в отдельном терминале):

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
ollama pull qwen3:4b-instruct-2507-q4_K_M
python -m uvicorn app.kt2_api:app --host 127.0.0.1 --port 8012
```

Откройте [демо КТ-2](http://127.0.0.1:8012/kt2). Спросите «Сравни канвасовые кеды, пляжные сандалии и бордовые дерби: какие пары на плоской подошве, а какая — на низком каблуке?», затем «Какая точная высота каблука в сантиметрах у бордовых дерби на низком каблуке?». Во втором случае карточка есть, но высота каблука не указана. `KT2_LLM_BASE_URL`, `KT2_LLM_MODEL` и `KT2_LLM_TIMEOUT_S` настраиваются отдельно от основного стилиста. По умолчанию используется Ollama на порту 11434. Chroma и модели эмбеддингов для этого режима не нужны.

**Повторить бенчмарк** из второго терминала в `backend/` (в том же Python-окружении):

```bash
python scripts/kt2_benchmark.py --base-url http://127.0.0.1:8012 --output kt2_data/capsule_reproduced
```

Набор: [30 карточек из 50](backend/kt2_data/corpus.json), [10 обычных вопросов и 5 ловушек](backend/kt2_data/questions.json). Карточки берутся из [`wardrobe_seed.json`](rag/data/wardrobe_seed.json) и [`wardrobe_capsule_extra.json`](rag/data/wardrobe_capsule_extra.json): по одному документу на вещь, без добавленных свойств. Вопросы проверяют подбор под повод, погоду, материалы и сравнение вещей; ловушки запрашивают свойства, которых нет в карточках. Для каждого обычного вопроса размечены эталон и три релевантных ID. Эталоны не передаются модели.

Раннер сохраняет `summary.json` и `per_query.json` в указанном каталоге. Recall@3 и MRR@3 считаются по 10 обычным вопросам; эвристическая Accuracy — по их ответам, Correct Rejection Rate — по 5 ловушкам. Здесь выбрано `k=3` для выдачи и расчёта MRR; слайд 42 предлагает согласовать глубину заранее. Ошибка модели или соединения не засчитывается как отказ.

**Прогоны по капсуле** (`qwen3:4b-instruct-2507-q4_K_M`, тот же корпус, вопросы и `k=3`, 15/15 запросов без ошибок в каждом):

| Вариант | Recall@3 | MRR@3 | Эвристическая Accuracy | Корректные отказы |
| --- | ---: | ---: | ---: | ---: |
| До фильтрации служебных слов | 96,67% (29/30) | 1,00 | 7/10 | 5/5 |
| Без частых служебных слов в запросе | 100% (30/30) | 1,00 | 8/10 | 5/5 |
| Тот же BM25, промпт с отдельной ссылкой для каждого свойства | 100% (30/30) | 1,00 | 9/10 | 5/5 |

[Исходный прогон](backend/kt2_data/capsule_run/summary.json) · [После правки поиска](backend/kt2_data/capsule_stopwords_run/summary.json) · [Итоговая сводка](backend/kt2_data/capsule_generation_run/summary.json) · [Выдача и ответы на все 15 вопросов](backend/kt2_data/capsule_generation_run/per_query.json).

- Q01: ответ верен по ручной сверке. Автооценка не распознала «лён и хлопок» как эквивалент «льна с хлопком».
- Q04: слова «в» и «как» раньше поднимали водолазку выше беговых шорт. После фильтрации в топ‑3 попали футболка, кроссовки и шорты; Qwen перечислила все три вещи со ссылками. Ни один ранее зачтённый ответ не потерял зачёт.
- Q06: раньше модель отказывалась при наличии всех трёх карточек. Теперь она отделяет цель пользователя от запрошенных фактов и указывает источник для каждого: высокая посадка у тёмно-синих джинсов, широкие штанины у светло-голубых, тонкая костюмная шерсть у палаццо. Выдача BM25 не изменилась.
- Q07: в предыдущем прогоне был неподтверждённый комментарий о застёжке водолазки; в итоговом его нет. Автооценка не проверяет все добавленные утверждения.

Метрики этого набора нельзя сравнивать напрямую с [архивом про мастерскую](backend/kt2_data/conclusions_run/analysis.md): изменились корпус и вопросы.

Для исходных учебных документов мастерской есть [отдельный бенчмарк BM25 с расширением запроса](backend/kt2_data/retrieval_feedback/analysis.md). На нём Recall@3 вырос с 83,33% до 100% при MRR@3 = 1,00. Чтобы повторить замер без Qwen, запустите из `backend`:

```bash
python scripts/kt2_benchmark.py --retrieval-only --output kt2_data/retrieval_feedback_reproduced
```

По умолчанию стенд использует капсулу. Для поиска по архивным учебным документам задайте `KT2_RETRIEVAL_PROFILE=workshop_feedback` при запуске и введите вопрос из [архива](backend/kt2_data/workshop_archive/questions.json) вручную.

Бенчмарк КТ‑2 оценивает поиск и ответы по карточкам, а не изменение состава готового образа в чате. Для точечных правок есть [отдельные сценарии поиска по категории](rag/data/slot_search_examples.json) и [тесты основного бэкенда](backend/tests/test_outfit_edit.py).

### Сценарий защиты

Для показа используйте [актуальную презентацию](AI_Stylist_Presentation.pptx); слайд 6 — бенчмарк и его ограничения. `slide_preview.*` и `slides_img/` — архивные экспорты КТ‑1.

1. **Основной Лукбук:** запустите Лукбук с реальным backend по инструкции ниже. В гостевом режиме добавьте вещи через «Гардероб → Базовая капсула». В новом диалоге спросите «Подбери лаконичный образ для деловой встречи в офисе». Затем: «Замени обувь, остальное оставь». Сравните две карточки: должна измениться только пара обуви.
2. **Стенд `/kt2`:** спросите «Для замены шорт сравни два варианта джинсов из капсулы и серые палаццо. Какие джинсы с высокой посадкой, у каких широкие штанины и из чего сшиты палаццо?». Покажите три утверждения со ссылками и отдельно выдачу BM25. Затем спросите «Какая точная высота каблука в сантиметрах у бордовых дерби на низком каблуке?». Карточка дерби будет в выдаче, но ответ должен сообщить, что точной высоты в ней нет.
3. **Результаты:** покажите четыре метрики при `k=3` и объясните незачёт Q01. Полный прогон можно повторить по команде выше, но для показа достаточно сохранённых выдач и ответов.

**Перед показом:** откройте оба сценария на компьютере защиты и сделайте пробные запросы, чтобы прогреть гардероб и модели. Для основного чата проверьте `VITE_USE_REAL_BACKEND=true`: на первом подборе финальное событие SSE должно содержать `source: "llm"` и `meta.retriever: "wardrobe_rag"`. Если глубину выдачи и MRR ещё не согласовали, уточните у преподавателя наш вариант `k=3`. Держите [сохранённые ответы](backend/kt2_data/capsule_generation_run/per_query.json) под рукой на случай сбоя демо.

**Проверка ответа сервером:** после модели каждый вывод сверяется с найденными документами. Документ, названный в тексте («по Д22»), становится источником вывода — раньше ссылка внутри текста давала ошибку 502. Число или шифр, которых нет в источниках и в вопросе, не выдаются за проверенные: искажённый повтор убирается, остальное помечается. Что именно сервер изменил, видно в поле `checks` и под ответом в демо. На 38 записанных ответах пяти прогонов слой изменил 7, не потеряв ни одного засчитанного факта; повторить без модели: `python scripts/kt2_replay.py kt2_data/conclusions_run`. Пропущенные условия из процитированных документов сервер находит, а выбирать из них нужные может второй короткий вызов модели (`KT2_COVERAGE_PASS=true`) — он выключен, пока не замерен на Qwen. [Разбор и план замера](backend/kt2_data/grounding_replay/analysis.md).

## О проекте

**12 STOREEZ | AI LOOKBOOK** — это интерактивный веб-сервис, позволяющий пользователю оцифровать свою персональную капсулу одежды и получать персонализированные формулы образов от виртуального стилиста.

### Ключевые возможности:
- **Telegram / ChatGPT-стиль диалогов:** многопоточная история переписок, возможность создавать неограниченное число новых консультаций, поиск по чатам и сохранение ответов.
- **Интерактивные лукбук-карточки:** готовые комплекты с описанием баланса фактур, советами по стилизации, сохранением в избранное и шерингом.
- **Полноэкранный каталог:** базовая демо-капсула на 50 вещей, фильтры по категории, подкатегории и стилю, поиск по вещам. Капсула дополняет личный гардероб, а не заменяет его.
- **Эстетика 12 STOREEZ:** натуральная палитра (экрю, кашемир, песочный, глубокий контрастный чёрный `#111111`), шрифты `Jost` и `Cormorant Garamond`.
- **Полная мобильная адаптация:** поддержка смартфонов и планшетов, нативная навигация, динамическая высота `100dvh` и модальные шторки (bottom sheets).
- **100% автономность:** работает без внешних серверов на первом этапе (симуляция RAG-пайплайна в клиенте, сохранение в `localStorage`, локальные векторные иллюстрации).
- **Дневная и вечерняя темы:** переключение Light / Dark режима в один клик.

## Быстрый запуск

### Требования
- Установленный **Node.js** версии 18+ или 20+ ([скачать Node.js](https://nodejs.org/))
- Менеджер пакетов **npm** (идёт в комплекте с Node.js)

### 1. Клонирование репозитория
```bash
git clone https://github.com/SachaXoDev/NIRS_AI_stilist.git
cd NIRS_AI_stilist
```

### 2. Установка зависимостей
```bash
npm install
```

### 3. Запуск в режиме разработки
```bash
npm run dev
```

После запуска терминал покажет ссылку:
```text
  VITE v8.3.4  ready in 150 ms

  ➜  Local:   http://localhost:5173/
  ➜  Network: use --host to expose
```

Откройте в браузере **`http://localhost:5173`**.

---

### 4. Запуск с настоящим бэкендом (необязательно)

```bash
# терминал 1 — сервер (подробности и PowerShell-вариант: backend/README.md)
cd backend
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m pip install -e ../rag
.venv/bin/python -m uvicorn app.main:app --port 8000

# терминал 2 — фронтенд
echo "VITE_USE_REAL_BACKEND=true" > .env.local
npm run dev
```

Для редактирования настроек куратора задайте `ADMIN_TOKEN` в `backend/.env` и перезапустите
сервер. Войдите в демо-аккаунт администратора и введите этот токен при сохранении в панели.
Не добавляйте токен в `.env.local` или `VITE_*`: это серверный секрет.
