# КТ-2: серверная проверка ответа на зафиксированных ответах модели

> Стенд КТ-2 с 27 ноября работает по капсуле Лукбука. Основная часть этого разбора сделана на
> прежнем наборе про мастерскую (`workshop_archive`); результат на капсуле — в разделе
> «Прогоны по капсуле» ниже.

Задача — полнота ответа и привязка каждого вывода к источнику при неизменной выдаче BM25.
Здесь измерено то, что не зависит от удачи с промптом: слой `app/kt2_grounding.py` применён к
ответам Qwen, уже записанным в пяти прогонах бенчмарка (38 ответов на обычные вопросы), и
результат заново оценён правилами `kt2_benchmark.py`. Модель при этом не вызывается, поэтому
выдача, промпт и текст модели в сравнении «до/после» одинаковы.

```bash
python scripts/kt2_replay.py kt2_data/conclusions_run   # любой каталог с per_query.json
```

## Что слой делает с ответом

| Ошибка модели в записанных ответах | Действие сервера |
| --- | --- |
| Документ назван в тексте, а не в ссылке: «…по Д22. [D23]» | Ссылка переносится в источники утверждения: `[D23] [D22]` |
| Ссылка `[D19]` вставлена внутрь текста | Раньше весь ответ отклонялся с HTTP 502; теперь ссылка переносится в источники |
| Значение взято из другого найденного документа (бокс Ш-2 со ссылкой на D07) | Этот документ добавляется вторым источником |
| Число искажено при переписывании («27 о К» вместо «2700 К») | Повтор уже сказанного убирается; единственное утверждение заменяется дословным предложением источника |
| Числа нет ни в источниках, ни в вопросе («ремонт стоит 200 рублей») | Утверждение остаётся, но помечается: «нет в источниках: 200» |

Итог, посчитанный из чисел источников (400 = 220 + 2 × 90), неподтверждённым не считается.
Слой ничего не сочиняет: он переносит ссылку или цитирует документ слово в слово. Отказ модели
он не трогает.

## Результат на записанных прогонах

| Прогон | Ответов | Изменено | Что изменилось |
| --- | ---: | ---: | --- |
| `conclusions_run` (текущая генерация) | 9 | 2 | Q08: D22 стал источником вывода о допуске; Q07: убран повтор с «27 о К» |
| `instruct_run` | 9 | 2 | Q04: 1998 получил источник D11; Q07: «27 о К» помечено как неподтверждённое |
| `stemming_only` | 8 | 1 | Q03: бокс Ш-2 получил источник D08 |
| `results` | 8 | 1 | Q06: «200 рублей» помечено как неподтверждённое |
| `examples_run` | 4 | 1 | Q09: шифр Л-14Д получил источник D26 |

Ни в одном из 38 ответов не потерян засчитанный факт и не нарушено соответствие ссылок
источникам (это проверяет тест `test_review_never_loses_facts_or_breaks_citations_on_recorded_answers`).
Ложных срабатываний проверки чисел на этих ответах нет: помечены только «27» и «200».

Эвристическая Accuracy текущего прогона не изменилась — 1/10: она считает формулировки фактов,
а слой исправляет источники и числа. По ручной сверке в [conclusions_run](../conclusions_run/analysis.md)
у Q08 было одно замечание — правило допуска из D22 упомянуто в тексте, но не процитировано.
После проверки D22 стоит в источниках этого вывода. Засчитывать ли теперь Q08, решает
проверяющий: автоматически это не подтверждается.

## Прогоны по капсуле

| Прогон | Ответов | Изменено | Помечено неподтверждённым |
| --- | ---: | ---: | ---: |
| `capsule_run` | 9 | 0 | 0 |
| `capsule_stopwords_run` | 9 | 0 | 0 |
| `capsule_generation_run` (итоговый) | 10 | 0 | 0 |

На карточках капсулы модель уже ставит ссылку на каждое свойство, чисел и шифров в ответах
почти нет, поэтому проверка ничего не меняет и ничего не помечает: метрики прогонов остаются
прежними (эвристическая Accuracy 7, 8 и 9 из 10). Польза здесь защитная: ответ со ссылкой
внутри текста больше не обрывается ошибкой 502, а в `parts` для каждого утверждения видно,
какой карточкой оно подтверждено.

Проверка сверяет числа, шифры и ссылки, но не смысл утверждения: неподтверждённый комментарий
без чисел (как про застёжку водолазки в `capsule_stopwords_run`) она не поймает.

## Полнота: что найдено, но ещё не измерено

Причина незачёта Q02, Q05 и Q07 при полной выдаче — пропущенные условия из тех же документов,
на которые модель сослалась. Функция `unused_sentences` находит их детерминированно: все
четыре предложения, названные в ручной сверке, попадают в список кандидатов.

| Вопрос | Пропущенное предложение процитированного документа | В кандидатах |
| --- | --- | :---: |
| Q02 | «Размытие лица вместо кадрирования не принимают; если срезаются плечи изделия, снимок переснимают.» [D05] | да |
| Q05 | «После показа выданную одежду принимают только из рук в руки у костюмерной стойки.» [D13] | да |
| Q05 | «Деревянная вешалка остаётся на площадке и в комплект не входит.» [D15] | да |
| Q07 | «Зелёные образцы «Шалфей» и «Мох» выглядели одинаковыми на столе при дневном свете.» [D20] | да |

Вместе с нужными в кандидаты попадают и пояснения, не нужные для ответа (в Q03 ответ полон, а
кандидатов пять). Дописывать их все значило бы выдавать пересказ документа за ответ, поэтому
выбор оставлен модели: при `KT2_COVERAGE_PASS=true` сервер делает второй короткий вызов, модель
возвращает номера нужных предложений (ответ ограничен схемой), и они добавляются дословно с
пометкой «Дословно из источника». Сбой этого вызова не отнимает уже готовый ответ.

Этот режим **выключен по умолчанию и на Qwen не замерен**; для капсулы он, скорее всего, не нужен: кандидатов там 4–8 на ответ, а итоговая Accuracy уже 9/10. Его потолок на текущей выдаче —
закрыть Q02, Q05 и Q07; сколько из этого даст модель и не начнёт ли она добавлять лишнее,
покажет только прогон:

```bash
KT2_COVERAGE_PASS=true python -m uvicorn app.kt2_api:app --host 127.0.0.1 --port 8012
python scripts/kt2_benchmark.py --base-url http://127.0.0.1:8012 --output kt2_data/coverage_pass_run
```

Смотреть нужно на три вещи: Accuracy и ручную сверку Q02, Q05, Q07; не появились ли лишние
цитаты в Q03, Q04, Q08; и время ответа — это плюс один вызов модели на каждый неотказной ответ.
Q01, Q06, Q09 и Q10 ограничены выдачей: нужных документов нет в top-3, генерация их не закроет.
